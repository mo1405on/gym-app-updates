# بوت واتساب للعمليات المحاسبية

نظام محاسبة مستقل (غير مرتبط ببرنامج إدارة الاشتراكات في هذا المستودع) يستقبل أوامر نصية عبر واتساب
ويسجّلها كقيود محاسبية بنظام القيد المزدوج (مدين/دائن)، مع إمكانية عرض الأرصدة والتقارير من داخل المحادثة.

## 1. القرارات المعمارية

| القرار | الخيار | السبب |
|---|---|---|
| الاتصال بواتساب | مكتبة غير رسمية [`@whiskeysockets/baileys`](https://github.com/WhiskeySockets/Baileys) | مجانية، لا تحتاج موافقة Meta ولا رقم أعمال موثّق، تعمل بربط QR كأي جهاز واتساب ويب. **المقابل:** تخالف شروط استخدام واتساب، ويوجد احتمال (منخفض لكن قائم) لحظر الرقم؛ يُنصح باستخدام رقم مخصص للبوت وليس الرقم الشخصي. عند نمو المشروع يمكن الانتقال لاحقاً إلى WhatsApp Cloud API الرسمي دون تغيير طبقة المحاسبة، لأن طبقة واتساب معزولة في `src/whatsapp/`. |
| قاعدة البيانات | SQLite عبر `better-sqlite3` | ملف واحد بدون خادم منفصل، مناسب لحجم الاستخدام (منشأة واحدة)، متزامن (synchronous API) وهذا يبسّط ضمان تناسق القيود المحاسبية. |
| نموذج المحاسبة | قيد مزدوج فعلي (دليل حسابات + سطور مدين/دائن) خلف واجهة "إدخال سريع" | يعطي صحة محاسبية حقيقية (كل قيد متوازن دائماً) بينما تبقى تجربة الاستخدام عبر واتساب بسيطة: المستخدم يكتب "قبض 500 اشتراكات" فقط، والنظام يبني القيد الكامل تلقائياً. |
| تحليل الأوامر | Regex/Keyword-based (بدون AI/NLU خارجي) | الأوامر محدودة ومعروفة مسبقاً، فلا حاجة لتكلفة أو زمن استجابة استدعاء نموذج لغوي خارجي؛ ويمكن إضافة طبقة NLU لاحقاً كخيار إضافي دون كسر الأوامر الحالية. |

## 2. البنية

```
whatsapp-accounting-bot/
  src/
    index.js                     نقطة التشغيل: يفتح قاعدة البيانات ويبدأ اتصال واتساب
    config/index.js              تحميل إعدادات .env
    whatsapp/
      client.js                  اتصال Baileys (QR، إعادة الاتصال، استقبال/إرسال الرسائل)
      commandHandler.js          الموجّه الرئيسي: تحقق صلاحيات → تحليل أمر → تنفيذ → رد
    nlu/parser.js                تحويل نص عربي حر إلى أمر منظّم (type + بيانات)
    accounting/
      ledger.js                  محرك القيد المزدوج: ترحيل، إلغاء، أرصدة، دليل حسابات
      textNormalize.js           توحيد الألف/الياء/التاء المربوطة والتشكيل لمطابقة النصوص العربية
    reports/reportBuilder.js     تقارير ملخّص الفترة وكشف الحساب
    session/sessionManager.js    حالة تأكيد مؤقتة للعمليات الكبيرة (تنتهي بعد 5 دقائق)
    auth/accessControl.js        صلاحيات المالك مقابل المحاسب
    db/
      schema.sql                 مخطط الجداول
      database.js                فتح القاعدة + ترحيل تلقائي + بذر دليل حسابات افتراضي
  data/                          قاعدة البيانات وجلسة واتساب (غير مرفوعة على git)
```

### تدفق معالجة الرسالة

```
رسالة واتساب واردة
   → whatsapp/client.js (استخراج النص والمرسل)
   → whatsapp/commandHandler.js
        1. accessControl: هل الرقم مصرّح له؟ ما دوره (owner/accountant)؟
        2. nlu/parser: تحويل النص إلى { type, amount, categoryText, ... }
        3. حسب النوع: تنفيذ مباشر عبر accounting/ledger.js
           أو تعليق العملية في session لو تجاوزت حد التأكيد (CONFIRM_ABOVE_AMOUNT)
        4. تسجيل العملية في audit_log
   → رد نصي يُرسل للمستخدم عبر واتساب
```

## 3. نموذج البيانات (القيد المزدوج)

- **accounts** (دليل الحسابات): كل حساب له نوع من خمسة: أصل، التزام، حقوق ملكية، إيراد، مصروف.
- **category_aliases**: يربط كلمات دارجة ("نقدي"، "اشتراكات"، "كهرباء") بحساب فعلي، لتسريع الإدخال دون كتابة اسم الحساب كاملاً. تُنشأ تلقائياً عند أول استخدام لتصنيف جديد.
- **journal_entries / journal_lines**: رأس القيد وسطوره. كل قيد يُرفض إذا لم يتساوَ مجموع المدين مع مجموع الدائن (`ledger.postEntry`).
- **audit_log**: كل أمر وارد من واتساب يُسجَّل (من أرسله، النص الخام، النتيجة) لأغراض التدقيق.

مثال: أمر `قبض 500 اشتراكات نقدي` يُترجم داخلياً إلى قيد متوازن:

```
مدين  الصندوق              500
     دائن  إيرادات (اشتراكات)      500
```

## 4. الصلاحيات

رقمان مصرّح لهما محدَّدان في `.env`:

- **OWNER_NUMBERS** (المالك): كل الصلاحيات — تسجيل قيود، إلغاء قيود، إضافة حسابات، تقارير.
- **ACCOUNTANT_NUMBERS** (محاسب): تسجيل قيود وعرض تقارير/أرصدة فقط، بدون إلغاء أو إضافة حسابات.

أي رقم غير مدرج يُرفض تلقائياً برسالة "غير مصرح".

## 5. الأوامر المدعومة (v1)

```
قبض <مبلغ> <تصنيف> [نقدي/بنك] [ملاحظة: ...]      سند قبض/إيراد
صرف <مبلغ> <تصنيف> [نقدي/بنك] [ملاحظة: ...]      سند صرف/مصروف
تحويل <مبلغ> من <حساب> الى <حساب>                 تحويل بين حسابين (مثلاً صندوق → بنك)
رصيد [اسم الحساب]                                 رصيد حساب معيّن أو الصندوق افتراضياً
الحسابات                                          دليل الحسابات كاملاً مع الأرصدة
إضافة حساب <اسم> <النوع>                          إنشاء حساب جديد يدوياً (المالك فقط)
تقرير اليوم | الاسبوع | الشهر                     ملخص إيرادات/مصروفات/صافي + أرصدة نقدية
كشف حساب <اسم> [من YYYY-MM-DD الى YYYY-MM-DD]     حركة حساب خلال فترة
حذف اخر قيد / الغاء قيد #<رقم>                    إلغاء قيد (المالك فقط، القيد يبقى بالسجل بحالة "ملغى" ولا يُحذف فعلياً)
مساعدة                                            عرض قائمة الأوامر
تأكيد / الغاء                                     تأكيد أو إلغاء عملية تجاوزت حد CONFIRM_ABOVE_AMOUNT
```

## 6. الإعداد والتشغيل

```bash
cd whatsapp-accounting-bot
cp .env.example .env   # ثم عدّل OWNER_NUMBERS برقمك الدولي بدون +
npm install
npm start
```

عند أول تشغيل سيظهر رمز QR في الطرفية — امسحه من واتساب على جهاز البوت عبر
"الإعدادات ← الأجهزة المرتبطة ← ربط جهاز". بعدها تُحفظ الجلسة في `data/auth/`
ولن تحتاج مسح الرمز مرة أخرى إلا إذا سُجِّل الخروج.

## 7. أفكار للمرحلة التالية (لم تُنفَّذ بعد)

- تصدير التقارير كملف Excel/PDF يُرسل كمرفق واتساب.
- إرفاق صورة الفاتورة مع القيد (استقبال `imageMessage` وربطها بسطر القيد).
- تقرير يومي/شهري تلقائي يُرسل دون طلب (جدولة عبر `node-cron`).
- طبقة اختيارية لواجهة "مستأجرين متعددين" (أكثر من منشأة على نفس البوت) لو احتجتها لاحقاً.
- الانتقال إلى WhatsApp Cloud API الرسمي إذا زاد الاعتماد على البوت وأردت تفادي مخاطر الحظر.
