# بوت واتساب للمحاسبة (قيود القبض والصرف)

نظام محاسبي **مستقل** (غير مرتبط ببرنامج إدارة الاشتراكات) يعمل كبوت واتساب: يستقبل رسائل نصية
بأوامر عربية بسيطة، ويسجّلها كقيود محاسبية (قبض / صرف) في قاعدة بيانات محلية، ويرد بتقارير ورصيد فوري.

## 1. الفكرة العامة

- المستخدم (صاحب العمل أو المحاسب) يراسل رقم واتساب البوت من جواله مباشرة.
- يكتب أمرًا بصيغة بسيطة، مثل:
  - `قبض 500 اشتراك أحمد #اشتراكات`
  - `صرف 200 فاتورة كهرباء #مصاريف_تشغيل`
  - `رصيد`
  - `تقرير اليوم`
- البوت يفهم الأمر، يسجّله في قاعدة بيانات SQLite محلية، ويرد برسالة تأكيد فيها رقم القيد والرصيد الجديد.
- فقط الأرقام المصرّح لها (Whitelist) يمكنها تسجيل قيود؛ أي رقم آخر يُرفض تلقائيًا.

## 2. لماذا هذه التقنيات

| القرار | الخيار المُختار | السبب |
|---|---|---|
| الاتصال بواتساب | مكتبة غير رسمية **Baileys** (`@whiskeysockets/baileys`) | تتصل مباشرة عبر WebSocket بدون متصفح/Puppeteer، خفيفة ومناسبة لسيرفر صغير. لا تحتاج حساب Meta Business API ولا تكلفة رسائل. **ملاحظة مخاطر:** هذه مكتبة غير رسمية تحاكي واتساب ويب؛ واتساب قد يحظر الرقم إن استُخدم بشكل مخالف لسياساتها (رسائل جماعية/سبام). للاستخدام الشخصي/الداخلي المنخفض الحجم المخاطرة منخفضة، لكن للاستخدام التجاري الواسع يُفضّل لاحقًا الانتقال إلى WhatsApp Cloud API الرسمي (الكود مبني بحيث طبقة "المُرسِل/المُستقبِل" منفصلة عن منطق المحاسبة لتسهيل هذا الانتقال). |
| قاعدة البيانات | **SQLite** عبر `better-sqlite3` | ملف واحد محلي، لا يحتاج سيرفر قاعدة بيانات منفصل، مثالي لبوت صغير/متوسط ويسهل عمل نسخة احتياطية (نسخ ملف واحد). |
| اللغة | Node.js (ESM) | نفس بيئة Baileys، ولا حاجة لـ runtime إضافي. |
| جلسة واتساب | ملفات auth محلية (`data/auth/`) | تُحفظ تلقائيًا بعد أول مسح QR، فلا حاجة لإعادة المسح كل تشغيل. |

## 3. المعمارية (Architecture)

```
جوال المستخدم (واتساب)
        │  رسالة نصية
        ▼
┌─────────────────────────┐
│   طبقة الاتصال (Baileys) │  src/whatsapp.js
│  - إدارة الجلسة/QR       │
│  - استقبال/إرسال الرسائل │
└───────────┬─────────────┘
            │ نص خام + رقم المُرسل
            ▼
┌─────────────────────────┐
│   طبقة الصلاحيات         │  src/auth.js
│  - هل الرقم مصرّح له؟    │
│  - admin أم member؟      │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│   طبقة تحليل الأوامر      │  src/parser.js
│  - تحويل النص إلى أمر     │
│    منظّم {command, ...}   │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│   منفّذ الأوامر            │  src/commands.js
│  - قبض / صرف / رصيد      │
│  - تقرير / حذف / مستخدمين │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│   طبقة البيانات           │  src/db.js
│  - SQLite (better-sqlite3)│
│  - entries / allowed_users│
└─────────────────────────┘
```

كل طبقة مستقلة عن الأخرى (مثال: `commands.js` لا يعرف شيئًا عن واتساب)، بحيث يمكن لاحقًا:
- تبديل Baileys بـ WhatsApp Cloud API الرسمي دون لمس منطق المحاسبة.
- تبديل SQLite بقاعدة بيانات أخرى (Postgres مثلًا) دون لمس المحلّل أو طبقة واتساب.
- إضافة واجهة ويب لعرض التقارير تقرأ من نفس قاعدة البيانات.

## 4. نموذج البيانات (Schema)

```sql
-- القيود المحاسبية
CREATE TABLE entries (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  entry_date   TEXT    NOT NULL,             -- YYYY-MM-DD
  type         TEXT    NOT NULL CHECK(type IN ('in','out')), -- قبض / صرف
  amount       REAL    NOT NULL CHECK(amount > 0),
  category     TEXT,                          -- تصنيف اختياري (#اشتراكات)
  description  TEXT    NOT NULL,
  created_by   TEXT    NOT NULL,               -- jid المُرسل في واتساب
  created_by_name TEXT,
  created_at   TEXT    NOT NULL,               -- ISO timestamp
  voided       INTEGER NOT NULL DEFAULT 0,     -- إلغاء منطقي بدل الحذف الفعلي
  voided_at    TEXT
);

-- الأرقام المصرّح لها بالتعامل مع البوت
CREATE TABLE allowed_users (
  jid   TEXT PRIMARY KEY,      -- رقم واتساب بصيغة jid
  name  TEXT,
  role  TEXT NOT NULL DEFAULT 'member'  -- 'admin' | 'member'
);
```

الرصيد = `SUM(amount WHERE type='in' AND NOT voided) - SUM(amount WHERE type='out' AND NOT voided)`.

القيود لا تُحذف فعليًا (سجل تدقيق/Audit Trail كامل) — الحذف يُنفّذ كـ "إلغاء منطقي" (`voided=1`) ولا يقوم به إلا `admin`.

## 5. الأوامر المدعومة

| الأمر | مثال | الوصف | الصلاحية |
|---|---|---|---|
| `قبض`/`دخل`/`وارد` | `قبض 500 اشتراك أحمد #اشتراكات` | تسجيل قيد دخل | member |
| `صرف`/`مصروف`/`سحب` | `صرف 200 فاتورة كهرباء #تشغيل` | تسجيل قيد خرج | member |
| `رصيد` | `رصيد` | عرض الرصيد الحالي | member |
| `تقرير` | `تقرير اليوم` / `تقرير الأسبوع` / `تقرير الشهر` | ملخص القيود للفترة (إجمالي قبض/صرف/صافي + تفصيل حسب التصنيف) | member |
| `اخر` | `اخر` أو `اخر 20` | آخر N قيد (افتراضي 10) | member |
| `حذف` | `حذف 45` | إلغاء قيد رقم 45 | admin فقط |
| `اضافة_مستخدم` | `اضافة_مستخدم 9665xxxxxxx اسم` | إضافة رقم مصرّح جديد | admin فقط |
| `مساعدة`/`help` | `مساعدة` | عرض قائمة الأوامر | الجميع |

يقبل المحلل الأرقام العربية (١٢٣) والإنجليزية (123)، والفواصل العشرية، والوسم `#تصنيف` في أي مكان بالسطر.

## 6. الأمان

- **Whitelist إلزامية**: أي رسالة من رقم غير مسجّل في `allowed_users` تُرفض برسالة "غير مصرّح"، ولا تُسجَّل أي قيود منها.
- **الأدمن فقط** يملك صلاحية الحذف/الإلغاء وإضافة مستخدمين جدد.
- **محادثات فردية فقط** بشكل افتراضي: البوت يتجاهل رسائل المجموعات (قابل للتفعيل عبر `ALLOWED_GROUP_JID` في `.env` إن رغب المستخدم بذلك).
- **جلسة واتساب محفوظة محليًا** في `data/auth/` — هذا المجلد حسّاس (يعادل جلسة دخول فعلية) ويجب عدم رفعه لأي مستودع عام؛ مُستثنى في `.gitignore`.
- **لا حذف فعلي للبيانات** (soft delete فقط) لضمان قابلية التدقيق.
- يُنصح بتفعيل نسخ احتياطي دوري لملف `data/accounting.db` (نسخ الملف كافٍ).

## 7. التشغيل

### المتطلبات
- Node.js 18 أو أحدث.
- جهاز واتساب حقيقي (رقم مخصص للبوت، يُفضّل رقم منفصل عن الاستخدام الشخصي) لمسح رمز QR مرة واحدة.

### الخطوات

```bash
cd whatsapp-accounting-bot
npm install
cp .env.example .env
# عدّل .env وضع رقم/أرقام الأدمن في ADMIN_NUMBERS
npm start
```

عند أول تشغيل، سيظهر رمز QR في الطرفية — امسحه من واتساب على الجوال
(الإعدادات ← الأجهزة المرتبطة ← ربط جهاز). بعدها تُحفظ الجلسة تلقائيًا ولن يُطلب QR مرة أخرى
إلا إذا حُذف مجلد `data/auth`.

### متغيرات البيئة (`.env`)

| المتغير | الوصف | مثال |
|---|---|---|
| `ADMIN_NUMBERS` | أرقام الأدمن (بصيغة دولية بدون +، مفصولة بفاصلة) — تُضاف تلقائيًا كـ admin عند أول تشغيل | `966554244571,966500000000` |
| `ALLOWED_GROUP_JID` | (اختياري) للسماح بالعمل داخل مجموعة واتساب معيّنة أيضًا | فارغ افتراضيًا |
| `DB_PATH` | مسار ملف قاعدة البيانات | `./data/accounting.db` |

## 8. التوسّع المستقبلي (اختياري، غير منفّذ الآن)

- تصدير تقرير Excel/PDF عبر أمر `تصدير`.
- ربط اختياري لاحق ببرنامج إدارة الاشتراكات (لو رغب المستخدم لاحقًا) عبر قراءة/كتابة ملف مشترك أو API.
- التبديل إلى WhatsApp Cloud API الرسمي عند الحاجة لموثوقية/حجم أكبر (طبقة `whatsapp.js` مصمّمة لتُستبدل بسهولة).
- تعدد "صناديق" (نقدي/بنك) بدل صندوق واحد، عبر إضافة عمود `account` لجدول `entries`.
